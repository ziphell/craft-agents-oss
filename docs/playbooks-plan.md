# 剧本（Playbook）— 设计方案

> 状态：**部分落地**——§12.5 里标 ✅ 的已实现并验证；未标的部分仍是设计。本文写「这是什么、边界在哪、代码在哪、为什么这样」，也是实施依据。
> 一句话：**剧本 = 一个能被触发、由 agent 执行、坏了能被修的 skill。**
> 读法：§0 先定名字（它决定后面所有文件名）；§2 是词汇与原语（本文的骨头）；§11 是**刻意不做**——后人别当 bug 修。
> 配套：[术语与文案规范](vocabulary.md)、[项目分层](project-layers.md)、[tweaks](tweaks.md)、[浏览器录制与视频理解](video-understanding-plan.md)、[价值论断](value-thesis.md)。

## 0. 名字（先定）

| 候选 | 为什么不 |
|---|---|
| `workflow` / 工作流 | **已被占用**——[价值论断](value-thesis.md) §2 用它命名 goal / spec / plan 那条线。重名会让"还差什么""plan 交给任务"整族话串味。 |
| `script` / 脚本 | 脚本会**重放**。这里的执行者是 agent，不是解释器。 |
| `automation` | `automations.json` 里那个"事件 → 动作"已经有主。 |
| `skill` | 剧本**就是一个 skill**（§3）——但"skill"表达不了"它有入口、有锚点、会跑"。 |
| **`playbook`（推荐）** | 一本给选手的打法册：**选手是 agent，带着判断执行**，不是照本宣科的机器。这正是它与"脚本"的分界，也是它比自然语言精准的原因。 |
| `runbook`（次选） | 语义同样准，但它在运维里绑着"故障响应"，比这件事窄。 |

**不要译成中文。** 像 `tweak` 一样保留英文：中文的"剧本"会读成 screenplay，"运行手册"会读成文档。

判据（沿用 [vocabulary.md](vocabulary.md)）：**名字说的是"这东西是什么形状"，不是"它有多聪明"。** 叫"理解""智能"就是把名字叫大了——上一课见 [tweaks](tweaks.md) 的"别叫理解"。

## 1. 定位

四条直觉，其它全从它们推出：

1. **默认什么都不存。** agent 就是**依据上下文重新执行**——不落盘、不出草稿。**只有人开口要"以后还能用"，才有剧本。** 这是[项目分层](project-layers.md)「义务只加在产物上，不加在过程上」的同一句话：**人说要留，才留**。
   （录制是另一回事：那是人的显式动作，它顺手留的侧车不算"存剧本"——但必须当场说清，见 §5.2②。）
2. **它是一个 skill，不是一个新容器，也没有自己的仓库。** 它**不提升到与 skill 同级**——多出来的那点生命周期，就显示在技能页上（§12）。
3. **它的入口是可选的。** 没有入口，它就是一个"可以开口要的 skill"；有入口，它才会自己开跑。
4. **它会跑、会坏、会被修。** 而修它的是 agent——因为它就是执行者。

所以它落在 **skill 与 automation 之间**：body 是 skill，entry 是 automation，接缝是一个字符串。

## 2. 词汇与原语

### 2.1 原语：三个文件、一个字段、一个字符串

| 原语 | 是什么 | 住在哪 | **谁写** |
|---|---|---|---|
| **剧本** | 意图 / 步骤 / 锚点 / 注意事项 | `{workspace}/skills/{slug}/SKILL.md` | 人 / agent（人确认后） |
| **命中** | 每个锚点上次匹配的事实 | 同目录 `hits.json` | **只由运行写**（照 tweaks 的 `hits.json`） |
| **侧车** | 录制时记下的动作与反应 | 影片旁边 `<录名>.events.jsonl` | **只由录制写** |
| **入口** | 什么时候开跑（可选） | `{workspace}/automations.json` 里一条 matcher | 人 |
| **接缝** | 把入口指到剧本 | prompt 里的 `[skill:slug]` | —— |

**就这些。** 判据是[项目分层 §1.1](project-layers.md) 那把尺子：这个能力**不加**工具、通道、绑定、页面、容器。

**「只由运行写」不只是句叮嘱，权限上也照这么分。** `hits.json` 在 Explore 模式的写白名单里（`apps/electron/resources/permissions/default.json` 的 `allowedWritePaths`），`SKILL.md` 不在——于是一个用 `--permission-mode safe` 起的**无人运行能说它看到了什么，却不能改写它被告知的步骤**。这正是 §1③「入口的许可写在入口上」那条规矩的同一把尺子。反过来说也成立：如果记录只能靠一个不在场的会话写，那「悄悄坏掉」永远不会有记录——而没人看着的运行恰恰是唯一需要它的那种。

`SKILL.md` 旁边放 `hits.json` 是安全的：`loadSkillFromDir` 只要求目录里有 `SKILL.md`，旁边的文件它不读、也不禁止（`packages/shared/src/skills/storage.ts`）。

### 2.2 词表

**按"谁写的"分栏——这是本文最要紧的一栏**：声明的东西人手写，观测的东西只由观察者写。

| 词 | 是什么 | 谁写 |
|---|---|---|
| **动作 (action)** | 一次操作；词汇表**就是** `browser_tool` 的命令面（navigate / click / fill / select / download …） | 观察到的 |
| **反应 (reaction)** | 页面因此做的事：导航 / 请求 / DOM 变化 | 观察到的 |
| **观察到的步骤 (observed step)** | 一个动作 + 紧随的反应，同一个时间戳 → **侧车的单位** | 观察到的 |
| **意图中的步骤 (intended step)** | 剧本里的一步：做什么、瞄哪个锚点、值是什么参数 | 声明的 |
| **锚点 (anchor)** | 一步瞄准的东西——**一个 CSS selector**（§5.2④ 说明为什么不是 role+name） | 声明的（写进 `SKILL.md`） |
| **命中 (hit)** | 锚点上次匹配的事实 | 观测的（只由运行写） |
| **草稿 (draft)** | 「观察到的」→「意图中的」的结果，给人看 | agent 提，人确认 |
| **演示 (demo)** | 人在共享窗口里把这个活做一遍 | 人 |
| **运行 (run)** | 一次执行 | —— |
| **自愈 / 修复** | 一趟内的意外 / 页面变了（§8） | 运行 |

### 2.3 骨头：一个对称

```
观察到的步骤  ──去噪──▶  意图中的步骤
   (侧车)                   (剧本)

声明的锚点    ──运行──▶  命中
 (SKILL.md)               (hits.json)
```

**同一个东西的两种时态。**「去噪」就是上面那次转换；下面那次是 tweaks 已有的那对表（`@target` ↔ `hits.json`），原样搬过来。

判据：**看一个词属于哪一栏，只问"它能不能被手写"。** 不能的（命中、侧车），就绝不能有第二个写者。

## 3. 形状：一个对象，两处文件，一条接缝

**剧本不是一个新类型，也不分类。** 它不是一个要被"识别出来"的文档类型——它是**"人开口要保存、于是被保存下来复用"的那一类 skill**。没有保存那一步，就没有剧本：agent 只是依据上下文重新执行（§1①）。所以 §15 里"怎么判定哪些是剧本"这个问题**不存在**。

因此：

- **没有判据、不扫、不标、不加 `isPlaybook`。** 那些都是"第二份描述"，必然过期，还会报假违例（[项目分层](project-layers.md) 的"约定大于配置"）。
- **技能列表上那枚 chip 不标"这是剧本"**，只标一个**事实**：**有入口**——它扫得到 `automations.json` 里一条带 `[skill:slug]` 的 matcher。那是列表里唯一会改变读法的事实，其余都是页面上的细节。
- **body** 住在 `{workspace}/skills/{slug}/`；**entry** 住在 `{workspace}/automations.json`。两处同一个 workspace，**整个 workspace 拷走仍然完整**。
- 两处之间**没有指针文件**：matcher 的 `prompt` 本身就是那个指针，也是真正会跑的东西——不存在"第二份事实"。

### 3.1 skill 的 meta 一个字不加

**不往 `SKILL.md` 的 frontmatter 里加任何字段**——不是"少即是多"，是每样东西都已经有家，而且都不是这里：

| 你可能想标的 | 它的家 | 为什么不在 meta |
|---|---|---|
| 有入口 / 什么时候跑 | `automations.json` 的 matcher | 那是**事实的来源**；两个文件都已被 watch（`packages/shared/src/config/watcher.ts` 跟随 `automations.json`，skills 亦然），界面**现算**即可，不需要一份会过期的缓存 |
| 无人运行的许可 | 同上，`matcher.permissionMode` | 入口本来就能给派生会话定权限模式。授予许可的是**设入口的那个人**，所以它写在入口上——也就是 tweaks「开关是同意」的同一条规矩 |
| 它是从哪来的（哪次录制 / 哪个会话） | **会话**（容器） | [项目分层 §1.2](project-layers.md) 的裁定：「**披露放在容器，不放在产物**」——`goal.md` / `*.spec.md` 连 `author:` / `generated-by:` 都不写。多写一份，就是一份手改文件的人不会去改的过期描述 |
| 它瞄准什么（锚点） | **正文**（`@anchor`，照 tweaks 的 `@target`） | 锚点是**逐步**的（哪一步瞄哪个），必须和步骤写在一起；agent 读的是正文 |

判据仍是 P10——**只加有 consumer 的字段**。`globs` 与 `alwaysAllow` 是两个现成的反例：被解析、在技能页上也显示，**运行时没人读**。别做第三个。

（`alwaysAllow` 要不要顺路接线是**独立**问题：它服务"工具级预批准"，而剧本的无人运行已经有 `matcher.permissionMode` 那条路。别为了剧本去复活它。）

### 为什么 body 用 skill，而不是另立容器

因为这正好是我们要的契约，而且**已经实现**：消息里出现 `[skill:slug]` → `BaseAgent.chat()` 前置"必须先用 Read 读 SKILL.md"的指令 → `PrerequisiteManager` 除 Read 外**拦下所有工具**，直到读完。

- `packages/shared/src/agent/base-agent.ts:904-1027`（`extractSkillPaths` / `formatSkillDirective`）
- `packages/shared/src/agent/core/prerequisite-manager.ts:211-283`

**"执行者必须先读这份文件"——这条不用我们发明，是 skill 白送的。** 而它恰好就是剧本最要紧的性质。

## 4. 两个产者，对称

| | 人做演示 | agent 记录 |
|---|---|---|
| 原始记录从哪来 | **侧车**（录制器写）+ 影片 | `session.jsonl` 的 `role:'tool'` 消息（`toolInput.command` + 结果） |
| 需要新建什么 | 录制器多写一个文件 | **无** |
| 覆盖 | 通用（含 canvas / 拖拽 / 桌面级） | 只覆盖 agent 亲手做的 |
| 精度 | 观察者给结构化动作；录像补观察者看不见的 | 命令与结果本来就是结构化的 |

**agent 那一路零采集**：`browser_tool` 每次调用都以 `role:'tool'` 消息落在会话历史里（`SessionManager.ts:8292-8415`，落 `session.jsonl`）。人只要说一句"把刚才那串总结成剧本"，agent 读自己的 transcript 就行——**比录像更准，因为那是命令与结果，不是像素。**

**人那一路也不必让 agent 在场观察**：见 §5。

## 5. 侧车：录制即观察

**不是 agent 在观察，是录制本身在观察。** 录制器一边录，一边把结构化事件写进影片旁边的一个文件：

```
demo.mp4            影片（存储形态；帧是它的视图）
demo.events.jsonl   侧车：观察到的步骤，与影片同一台时钟
```

**按路径相邻、同名不同后缀**——没有索引、没有注册表（约定大于配置）。

三条理由，一条比一条硬：

1. **同一台时钟是构造出来的，不是对齐出来的。** 两个文件同刻起、同刻停；不需要事后拿帧的 `offsetMs` 去对事件时间戳。
2. **不需要"演示模式"。** 观察者是录制器装的，**不持有 tab**（注入不持有——tweaks 的注入器本来就不持有）。人是按他本来就会按的那个录制键。
3. **agent 仍只是"读文件的人"。** 这正是本仓库的模型：工具只认文件。人录完就走，agent 事后读侧车。

**这是 [video-understanding-plan](video-understanding-plan.md) §6.2d 那条"按路径可查的线索"的正式形态**：那条线索只服务"抽帧默认策略"，侧车是它的完整版——同一份文件，多个消费者各取所需。

### 5.1 事件从哪来

| 通道 | 现状 | 覆盖 |
|---|---|---|
| 导航 | **已有**：tab 的 `did-navigate` / `did-navigate-in-page` / `will-navigate`（`browser-pane-manager.ts:6496,6536,6633`） | 地址变化 |
| 网络 | **已有**：`ses.webRequest.onBeforeRequest / onCompleted / onErrorOccurred`（`browser-pane-manager.ts:6055-6086`） | 请求与响应 |
| **页面内的用户动作** | **新建**：注入一个观察者 | 点了哪个元素、填了哪个字段 |

**所以"人演示"这一侧要新建的只有一样：页面内的观察者。** 主机侧的导航与网络**已经在了**（`browser_tool` 的 `network` 就是它的出口）。

观察者复用 tweaks 的注入路径（`Page.addScriptToEvaluateOnNewDocument` / `addInitScript`，`browser-cdp.ts:1570`、`tweaks-injector.ts`），跑在**页面自己的世界**（和 tweak 同一个世界）。回传通道（binding 还是 console）是实现时的选择，不进本文。

### 5.2 四条必须一起守的

① **侧车对 `video_tool` 必须是可选的。** [video-plan §6.1](video-understanding-plan.md) 立的规矩是"抽帧与理解只认文件；录制只是产出一个文件"。所以 `understand` 的签名**一个字不改**；读侧车的是**另一个消费者**（剧本作者）。有就用、没有就按默认——"加分项，不是前置条件"。

② **必须在录制时说出来。** 那个按钮今天的意思是"录屏"；加上"同时记下你点了哪个元素、填了哪个字段"，意思就变了。**按下去的时候**要可见，否则是人不知道自己在录什么。
✅ **已做**：录制中那条红从只显示计时，变成 `0:07 · 点击与输入已记下`——**按下之后立刻出现**，所以这次按下是知情的。放在**常驻可见**的位置而不是悬停提示里，是因为"要可见"不是"悬停可见"。（代价：红条变长，窄窗口下会挤。）

③ **值记，但"自称秘密"的字段不记。** `fill` 带上填了什么——否则"搜索框"这一步等于没写内容。**例外写在字段自己的声明上**：`type=password`、或 `autocomplete` 指名凭据的，只记字段名（不是靠猜字段的标签，是读它自己的声明）。判据：这个文件会躺在 `Downloads` 里，被人递给别人。

④ **侧车的描述不是锚点——两种东西，各有各的用途。** 这是**已定的结论**，不是遗留问题：

| | 形状 | 用来干什么 | 谁产出 |
|---|---|---|---|
| 侧车里的 `target` | `{tag, role, name}` | **给人/agent 读懂**"他点了哪个东西" | 观察者，从 DOM 属性推 |
| `@anchor` 里的锚点 | **CSS selector** | **给运行查得到** | 人 / agent 写下 |

**为什么锚点必须是 selector**：因为要能被**查**。仓库里已经有一个真的选择器检查器（tweaks 的 `buildSelectorMatchScript`），而 role+name 要的是 AX 树——那是主进程的东西，agent 拿不到；观察者按 DOM 属性推出来的 role 也不是 AX 树的 role（实测：一个可点 `<span>` 回来是 `role:"span"`）。两套若能"同源"当然好，但那是要求一个不存在的来源。

**代价写在明处**：从"侧车读到的他点了什么"到"`@anchor` 里写哪个选择器"，中间是**人/agent 的一次翻译**，没有工具代劳。这一步不能假装不存在——它正是"观察到的步骤 → 意图中的步骤"（§2.3）落到实际文件里的样子。

### 5.3 一个白得的性质

CDP screencast **只在重绘时出帧**（[video-plan §5.2](video-understanding-plan.md) 那条"静态页面必然断"的坑）。侧车与帧**无关**：页面一静，动作记录照样在走。**它补上了影片的盲区。**

### 5.4 录制不过滤（实测）

侧车**只报告事实，不做筛选**——一筛就成了"录制在替人判断"，而判断是去噪那一步的活（§6）。

**实测**（2026-10-03，一次搜索 + 两次点图，21 秒）：**175 行里只有 5 行是导航**，其余 168 行是请求，且绝大多数是 `image` / `script` / `ping` / `stylesheet` / `font`——第三方埋点与资源。**读者要的骨架是那 5 行，不是那 168 行**，所以过滤属于 §6，不属于这里。

同一次录制顺手验到的：`status:304` 与 `status:0 + error:"net::ERR_BLOCKED_BY_ORB"` 都照原样记下；`ms` 单调；末行 `seconds` 与末条 `ms` 对得上。

## 6. 去噪 → 草稿（人开口才做）

**这一步不是默认跑的。** 人没开口要"以后还能用"，就没有草稿——agent 只是依据上下文重新执行（§1①）。人开口之后，才先把原始记录收齐（人那边是侧车 + 影片，agent 那边是 `session.jsonl`），再去噪。

去噪是**意图判断**，所以它必须可被纠正、且**点名**。草稿三部分：

| 部分 | 是什么 |
|---|---|
| **步骤** | 判定在意图内的动作，按序（→ §7 的「意图中的步骤」） |
| **丢弃** | 判为噪音的，**每条附一句理由**：误点 / 探索 / 环境性（登录、关弹窗）/ 重复 |
| **待定** | 拿不准的，转成**问题**而不是猜："你在这里停了 5 秒，是等它加载，还是你在看？" |

然后**人校对**，确认后才落盘。

**为什么必须点名、必须给人看**：去噪是对"他想干什么"的判断，而判断不能自问自答。[项目分层](project-layers.md) 墓园里 `reviews/` 的死法就是"唯一的写者就是干这份活的 agent"——去噪不能重蹈。

## 7. 落盘

人确认后，agent（它是执笔者）写两处、只写两处：

1. `{workspace}/skills/{slug}/SKILL.md` —— 意图、**意图中的步骤**、**锚点声明**、注意事项（含"上一次修了什么"）。
2. `{workspace}/automations.json` —— 一条 matcher，`prompt` 里写 `[skill:slug]`。

**入口是可选的**：只有 skill、没有 matcher，它就是一个"可以开口要的过程"——那本来就是一个 skill。所以**手动那一路零新概念**。

### 7.1 一个已经存在的坑

文档 `apps/electron/resources/docs/automations.md:116` 说 prompt 里用 `@skill` 能引用 skill——**代码里不是**：`@` 只被 `parsePromptReferences` 认出来、被 `resolveAutomationMentions` 匹配到 slug，然后 **`skillSlugs` 只用来预启用该 skill 的 `requiredSources`**（`SessionManager.ts:6479-6491`），**不加载 SKILL.md**。真正能触发的是**方括号**（`TaskRunner.ts:968` 与 `apps/cli/src/index.ts:1420` 就是这么写的）。

**要么修文档，要么修代码；在定案之前，剧本必须写 `[skill:slug]`。**

### 7.2 锚点的声明语法：`@anchor`（**已定，已实现**）

写在**步骤行自己的 markdown 注释**里，值是 CSS selector：

```markdown
- Press Export. <!-- @anchor .toolbar .export -->
```

选它的两个理由：它对读的人**渲染成空**（markdown 注释）；而 `markers.ts` 的 `cleanMarkerValue` **本来就会剥掉 `-->`**——一行新解析都不用写。

（fenced block 是当初的另一个候选，放弃：锚点属于**某一步**，离了那一步就读不懂。）

## 8. 执行与修复

```
入口 → session → [skill:slug] → 读 SKILL.md（拦到读完） → agent 驱动共享窗口
```

每步：**声明的锚点是快路径**（命中就不必再想）；遇到情况就分类——**三类，不是两类**：

| 遇到的情况 | 做什么 | 动不动文件 |
|---|---|---|
| **这一趟的意外**（超时、抖动、A/B） | 自愈：重试 / 换个走法 | **不动** |
| **页面变了**（锚点结构性消失） | agent 改 `SKILL.md` 的锚点声明，**并在这一轮里说出改了什么** | **改，且露出来** |
| **需要人**（登录过期 / 权限不足 / 验证码） | **停下来，说清卡在哪** | **不动** |

**第三类是补上的，而且是三类里唯一"必须等人"的**：它既不是意外（重试无用），也不是页面变了（文件没错）。没有这一档，定时入口最常见的失败会被归进"意外"，然后一直重试到超时——正是这套设计要杀死的"悄悄坏掉"。（也正对上[价值论断 §6](value-thesis.md) 的"不是无人流水线，交接点由人按"。）

**随之而来的规矩：无人入口只适合幂等的动作。** 让一个定时入口去"提交""下单""导出一份会累加的副本"，就是重复动作的来源——**这类动作必须有人按**。不为此新增审批机制（task 那套 `kind: approval` 属于 coding 那条线，不搬过来）。

**这是全套设计唯一的纪律：一趟的意外不改文件；只有结构性失配才改，且改动要说出口。** 不守它，文件会漂成没人写过的东西——正是 [tweaks](tweaks.md) 的 `hits.json` 与已删的 `reports/` 一族反复要杀死的那个失败模式。

## 9. 锚点与命中

拆两半，**consumer 明确是"修复环 + 运行报告"**：

- **声明**：写进 `SKILL.md`（§7.2）。
- **命中**：`hits.json`，**只由运行写、绝不手写**（照 tweaks）。

**没有它，"页面变了"与"这次跑糟了"分不开**——那正是 `@target` 当初存在的全部理由：让"它停止匹配了"与"它从来没匹配上"成为两件说得清的事。

**一条必须写明的差别（是代价，不是缺陷）**：tweaks 的 `hits.json` 由**执行者（代码）**写，忘不了；剧本的执行者是 **agent**，而推它写的只有指南里那一段话。所以 **`hits.json` 可能根本不存在**。

那就不存在——**但读它的人不得把缺席解释成"匹配过"**：

- 没有文件 = **没有一次运行检查过**；
- 有文件、某个 selector 没有 `lastMatchedAt` = **自留下记录以来它没匹配上**；
- 有旧时间、没有新时间 = **它停止匹配了**（页面变了）。

这三句就是将来技能页那个分区的文案判据。**不为此新增"必然写"的机制**——那要新工具或新通道，违反 §2.1。这跟 §3.1 的"别加没人读的字段"是同一条的另一面：**一个文件可以没有写者，只要没有任何东西假装它被写过。**

## 11. 刻意不做

- **不做字面重放的 runner。** 执行者是 agent（P2）；"重放"会把它降级成 RPA，也就丢掉了"能修"。
- **不做剧本专属页面 / 列表 / 导航项，不建 `playbooks/`。** 家是技能页（P9）；一个"名字 + 状态 + 几条事实"的东西不该有自己的页面形状。
- **不自动保存，也不自动出草稿。** 人开口才有草稿、才落盘（P7、P11）。
- **不做"这个活值不值得复用"的自动判断。** 那是人的决定，不是系统的——所以也没有"哪些是剧本"的判据（P12）。
- **不做实时阈值找切点。** [video-plan §7](video-understanding-plan.md) 已经否过。
- **不做云端 headless。** 窗口在本机、你看得见——见[价值论断 §6](value-thesis.md)。
- **不给 `SKILL.md` 的 frontmatter 塞新字段**（入口放 `automations.json`）。`globs` / `alwaysAllow` 是前车之鉴。
- **不叫"智能""理解"。** 见 §0。
- **不给无人运行加通知机制。** 定时入口派生的**本身就是一个会话**（automations 的 prompt action 就是这样），所以"运行报告"的家就是那个会话——人在会话列表里看得见它。**不学 [video-plan](video-understanding-plan.md) 的"后台事件推一条"**：那条是为录制设的，因为录制不发生在会话里；这个已经在了。
- **剧本只认 workspace 层。** body 在 `{workspace}/skills/`、入口在 `{workspace}/automations.json`、`hits.json` 在同一个 skill 目录——三处同层。global / project 层的 skill 仍然是 skill，但**不是剧本**：入口这一半本来就是 workspace 级的。这是**有意的收窄**，不是漏掉的。
- **不给"记不记值"加开关。** 录值已经有一道闸（字段自称秘密的挡掉，§5.2③），再加开关要一个偏好项加一处界面，成本与收益不成比例；而人要控制它，最朴素的办法本来就是**不往那个框里打**。固定保存到应用自己的 `records/` 已经把暴露面降下来了（§5）。

### 12.1 创建流程是复用的，不是新建的

**创建 skill 早就有两条现成路，剧本只用其中一条的一半：**

| 现成的 | 在哪 | 复用哪一半 |
|---|---|---|
| **UI**：`EDIT_CONFIGS['add-skill']` | `components/ui/EditPopover.tsx:384-401`；触发在技能列表空态与全局工具栏 | 整套：popover **自己承载一个会话**、把 `<edit_request>`（`context` + 用户那句话）递给 agent、agent 去建、建完自校验。加一条 `add-playbook` 就是**一个注册项 + 几个 i18n key** |
| **CLI**：`craft-agent skill create / update / validate` | `config/cli-domains.ts:38-49`（`skill` 域的 policy）、`resources/docs/craft-cli.md` | **写入与校验那一步**。系统提示本来就写着"Prefer `craft-agent` CLI over direct file edits for … skills" |

所以 §2.1 那句"不加工具、通道、绑定、页面、容器"是**兑现的**，不是口号：连"创建"都是借的。

**唯一不能照抄的一处**：`EditContext` 是**静态串 + 一个 `filePath`**（`EditPopover.tsx:95-116`）——`add-skill` 描述的是**意图**（"创建一个 skill"），它**指不到那次干活**。而剧本是从**记录**里提出来的。于是：

- **人在会话里刚干完活** → 他就在那儿说一句，agent 读自己的记录（§4）。**这是自然的主路**，零管线。
- **要一个入口/按钮** → `add-playbook` 的 `context` 必须能说出**记录在哪**（会话 id / 侧车路径），这是 `add-skill` 给不了的一格。

（这一格就是 §15 U8 剩下来的问题。）

## 12.5 实施顺序

判据照 [video-plan §9](video-understanding-plan.md)：**先做能独立验证的那一段**——依赖方向是"agent 记录那一路零采集（§4）"，所以它先跑。

| # | 切片 | 依赖 | 怎么独立验证 |
|---|---|---|---|
| **1** | **指南**：`apps/electron/resources/docs/playbooks.md` + `DOC_REFS.playbooks` + 系统提示一行 | 无 | 做一遍浏览器活 → 说"把它存成剧本" → agent 读指南 → 出**草稿三部分** → 确认后用 `craft-agent skill create` 写出、`skill validate` 过 |
| **2** | **入口的可见性**：技能列表一枚 chip（有入口）+ 技能页「何时运行」 | 1 | 给某个 skill 在 `automations.json` 里加一条 `[skill:slug]` → 列表出现 chip、页面出现分区 |
| **3** | **侧车**：录制器写 `<录名>.events.jsonl`（先只记已有的导航/网络，页面观察者随后） | 无（可与 1 并行） | 录一段 → 影片旁边出现侧车，事件时间戳与帧对得上 |
| **4** | **锚点与修复环**：`@anchor` 声明 + `hits.json`（只由运行写）+ §8 的失配分类 | 1、2 | 改页面让某锚点消失 → 跑 → 判为"页面变了" → 文件被改、报告说出改动；反面：一次抖动 → **文件没动** |

**第 1 步刻意不含锚点**（只到"步骤用具体到找得回来的话写明目标"）：机器可读的 `@anchor` 要么等到第 4 步有消费者，否则就是 [§3.1](#31-skill-的-meta-一个字不加) 说的第三个"解析了没人读"的字段。

**已落地**：

- **第 1 步**：`resources/docs/playbooks.md` + `DOC_REFS.playbooks` + `prompts/system.ts` 的一行。
- **第 2 步**：判据 `renderer/lib/skill-entries.ts`（**现算**，靠 `parseMentions`——和 agent 侧同一个解析器，不可能漂移）；技能列表的 chip；技能页「何时运行」；7 个 locale 各两个键。
  **判据只数"开着的"入口**：关掉的 automation 不跑它，那个 skill 就不该说自己会自己跑——与 tweaks 的"关 = 不在跑"同一条。所以列表那枚 chip 的文案是「会自己运行 / runs on its own」，不是「有入口」——**标的是会发生的事，不是配置里存在的东西**。
- **第 3 步**：`recording-sidecar.ts`（`<录名>.events.jsonl`，与影片同一台时钟）；`TabRecorder` 在 `arm` 开、`finish` 关，并新增 `noteEvent(tabId, event)`；`BrowserPaneManager` 在四处喂事件——`did-navigate`、`did-navigate-in-page`、`webRequest` 的 `onCompleted` / `onErrorOccurred`。
  **只记"页面做了什么"（导航 + 请求），不记"人点了什么"**——后者要页面里的观察者，是第 3 步之后的事。**写者只有录制器**（照 `hits.json` 的规矩）；**一次事件写给这张 tab 的每一路录制**（人和会话可以是两路，页面只做了一件事）。**暂无条数上限**——见 U5。
  ✅ **已实测**（2026-10-03，真人按录制键）：指南同步到 `~/.craft-agent/docs/`；三次录制都在 `Downloads` 落下同名侧车；`navigate` 的**两条路**（`inPage` 与整页）都记到了；`start` / `stop` 首尾俱全；`ms` 单调且与 `seconds` 对得上。实测数据见 §5.4。
- **第 3 步（续）· 页面观察者**：`recording-observer.ts`。录制期间把一个小脚本放进这张 tab——**init script 管未来的文档，注入管眼前这一份**（录制是关于"现在"的，与 tweak 的"只管下一个文档"正相反）；只报 `isTrusted` 的动作（页面自己 `click()` 不算人做的）；`click` 带 `{tag, role, name}`，`fill` 另带 `value`（**自称秘密的字段不带**，§5.2③）；回传走**带前缀的 console 信号**（照 `THEME_COLOR_SIGNAL_PREFIX` 那条现成的路，识别后不进 console 日志）。
  ✅ **已实测**（真人录一段），并**当场抓出两个 bug**：字段的 `name` 曾被读成它的内容（textarea 的名字成了里面那句话）、以及按 `type` 判角色那段曾被 `ROLE_BY_TAG` 短路成死代码（提交按钮报成 textbox）。两者都已修、都有测试钉住。
- **第 4 步**：`skills/anchors.ts`——`@anchor <css>` 写在**步骤行自己的 markdown 注释**里（`cleanMarkerValue` 本来就会剥 `-->`）；`hits.json` 的读 / 合并 / 写 + `getSkillHitsPath`；类型进 `skills/types.ts`（零依赖，渲染层将来可直接读）。**写者是一次运行**（跑它的 agent），且只写它真看到的——没有时间就是"从没匹配上"，有旧时间没有新时间就是"页面变了"。指南已把这三样写给 agent。
- **第 5 步（收尾）· 录制时的说明**：浏览器工具栏那条录制中的红条，从只显示计时改成 `0:07 · 点击与输入已记下`（§5.2②）。**这是把"知情"放回按钮上的唯一一处代码**——在此之前，值已经被记下而人不知情。
- **第 6 步 · 「上次运行」分区（§12）**：`skills:get` 在**读的时候**把 `anchors` 与 `hits` 附在 skill 上（`LoadedSkill` 是 re-export，所以渲染层不用新通道）；技能页据此出一个分区。**文案是那条规矩的落地**：没有记录时说"还没有一次运行检查过"，**不显示成空表格**；某个 target 没有时间说"没匹配上"，而不是显示成"成功但缺个日期"。

## 14. 验证

**两条对称闭环，一条反例：**

1. **agent 记录**：让 agent 做一遍 → "总结成剧本" → 草稿（含丢弃与待定）→ 确认 → 写出 `SKILL.md` + matcher → 再跑一次 → 锚点命中。
2. **人演示**：按录制键（说明可见）→ 人操作（**故意含一次误点、一次多余滚动**）→ 侧车落盘 → "整理成剧本" → 草稿把那两下**点名丢弃** → 确认 → 同上。
3. **反例（必须过）**：制造一次网络抖动 → 自愈 → **文件必须没动**。改了就是纪律破了。

漂移再来一条：改页面让某锚点消失 → 跑 → 那步失配 → 判为"页面变了" → 文件被改、报告说出改动。
