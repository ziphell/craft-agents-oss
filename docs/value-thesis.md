# 价值论断 — 看 / 想 / 画 / 做 / 长期生效

> **定位**：本文写「这个版本的核心改造合起来值什么、在什么场景下成立、以及不声称什么」。
> 它**不写实现**：工作流那条线的机制在 [项目分层](./requirements/project-layers.md)（拿什么、不拿什么见其 §1.2），
> tweaks 的机制在 [tweaks](./requirements/tweaks.md)，浏览器与 drawio 在各自的开发文档里。
> **读法**：改这条线之前先看 §5「不声称的」——那里的每一条都是一次说错话换来的边界。

---

## 1. 论断

这个版本把「**看**（浏览器 / 媒体理解）— **想**（`goal` / `*.spec.md` / `*.plan.md`）— **创作**（drawio / GenOffice 文档 / 媒体生成与剪辑）— **做**（代码与任务）— **长期生效**（tweaks）— **连**（远程连接与设备）」放进**同一个工作区**和**同一个文件夹**，而且每一环的产物**都是文件**。

所以价值不在单点能力，而在**交接处没有损耗**：

- 不需要把浏览器里看到的东西**搬进**文档；
- 不需要把图从画图工具**搬进**需求；
- 不需要把需求**复制成**另一个工具里的任务描述。

每一环的输入就是上一环留在盘上的那个路径。

---

## 2. 六件事各自解决什么

| 能力 | 机制（事实） | 替代掉的手工动作 |
|---|---|---|
| **看（浏览器 / 媒体理解）** | 浏览器：工作区里**每个 profile 一个**窗口，同一 profile 下的人与所有会话共用。媒体理解：`call_llm`（图片）、`recording_tool understand`、`asr_tool transcribe`、`img-tool text` | 「agent 跑一趟，再口述给我听」「把图/录音发给别人问」——现在都是**同一个现场** |
| **工作流** | 一个会话一个 `mode`（`goal` / `spec` / `plan`，一次一层）；产物是 `goal.md` / `*.spec.md` / `*.plan.md`，家是**该项目的文件夹**；报告是项目页**现读盘** | 「需求写在聊天里，或散在几个文档里」 |
| **创作（图 / 文档 / 媒体）** | 三类产物都是文件：**图**——`.drawio` 由 agent 用 `Write` / `Edit` 写，`drawio_tool` 画出并导出（`--editable` 把文档装进 svg，对方在 draw.io 里改完递回）；**文档**——GenOffice 的 docx / xlsx / pptx / pdf 宿主，人和 agent 编辑**同一份**文件，带作品库与版本；**媒体**——`media_tool` 生成的图片 / 音频 / 视频，区分可编辑的**工程文件**与不可变的**导出物** | 「截图 → 发给我 → 重画」「导出文档 → 换工具改 → 再传回来」「下载素材 → 用剪辑软件拼」 |
| **tweaks** | 一个 tweak = 一个文件夹（`tweak.json` 声明 `matches` 与 `enabled`，加 `tweak.css` / `tweak.js`）。**装一次，之后每次页面加载都生效**——在普通浏览器里，这个 app 在不在附近都一样；同一批文件还能构建成一个浏览器扩展 | 「对着不属于我的后台，每次都手工改一遍」 |
| **coding** | 项目带着一个**工作目录**（代码、命令、测试真正跑的地方），这几层文档住在**项目的文件夹**里——两个地方，同一个容器。`plan` 交给任务生成器落成 `task.yaml` 的 DAG，每个节点派生一个子会话，`kind: approval` 的节点停下来等人 | 「把需求文档重写一遍，放进任务工具」 |
| **远程与设备** | workspace 的文件与执行留在所属机器；desktop / webui / CLI / Android 只是接入点。远程浏览器窗口、设备能力（exec / fs / browser / computer）都连到同一个 workspace | 「把文件搬到本机再跑，或换一台机器就换一套上下文」 |

## 3. 「有机结合」是共享同一套底座

六件事能连起来，是因为它们**共用同样几样东西**——所以加一个能力**不需要加一套机制**：

1. **同一个逻辑文件夹。** 图、材料、需求、方案都在同一个项目下；链接可以爬出文件夹，所以项目之间也能指。文件物理上在 workspace 所属的机器上（见第 5 条），客户端换掉不影响路径语义。
2. **同一个窗口，可能不在你面前。** 工作区里每个浏览器账号（profile）一个窗口，同一账号下的人和会话共用——**观察是共享的**，不是转述。远程连接时，这个窗口在 hub 或另一台机器上，人通过客户端看同一个 surface，而不是同一块屏幕。
3. **同一条写链（宿主自管的保存除外）。** 防抖写回、写前重读、外部改动跟随或问人（`keepMine` / `reloadFromDisk`）；drawio、markdown、html 三处复用同一条。GenOffice 文档由内嵌宿主负责保存与冲突，但共享同一条原则：**人机同改一份文件是一件事，不是三个功能。**
4. **同一种判定。** 报告只数盘上的**事实**，例如**链接指向不存在的文件**、**图与它旁边的 `.drawio` 对不上**。所以这些能力能出现在**同一份报告**里——需求文件夹那两条告警就是这么来的。
5. **同一个 workspace 归属。** 文件和执行发生在 workspace 所在的机器；desktop / webui / CLI / Android 只是接入点。换设备不产生第二份数据，也不改变「产物是文件、交接是路径」这套语义。

## 4. 六个场景走一遍

**竞品调研。** 在共享窗口里打开竞品页面（要登录的页面，你登一次，会话就看得见）→ **要留的东西你说了就当场落盘**（截图、导出的页面、`research/` 里的笔记）→ 图用 `.drawio`：agent 写 XML、就地画出来；需要你改的那张用 `--editable` 导出，你在 draw.io 里改完递回来 → 结论写成 `*.spec.md`（只写「要什么」，不写「怎么做」）→ 项目页把它列出来。
**全程没有一步是「把浏览器里的东西复制到文档工具」。**

**深度研究。** 多轮查证之后，**结论落盘**。这条的价值不在「查得深」，在**结论不留在对话记录里**：换一个会话、换一个人、换一个模型，都从**文件**开始，而不是从「你记得的那次对话」。真正稀缺的是**「我为什么这么判断」的留存**——文件是唯一不依赖某个工具还活着的形式。

**但留存由人驱动。** 这里**不对探索过程设义务**：「每一步都留一份文件」会把压力全压在 agent 身上，而产出的多半是没人回头看的**过程残渣**——那套 `research/` 落盘就是这么被删掉的。**人说要留，才留**，那就留成普通文件（判据见 [项目分层 §1](./requirements/project-layers.md)「义务只加在产物上，不加在过程上」）。

**需求分析。** `goal` → `spec` → `plan`，三层各有硬边界（需求不许写怎么做、方案不许改意图、目标不许写细节）；不切模式则**零注入、零痕迹**，普通项目不受打扰。人问「还差什么」时：`plan` 层不只读文件夹里的断链与陈旧图，还把同词干 `spec` 要的东西与手里的步对一遍，说出哪些没有对应的步——**读、不落盘、不成数字**。

**Coding。** 上文那条链在这里首尾相接：`plan` 交出去 → 生成器读这份文件、把它写明的步骤变成节点（**不重新发明分解**）→ 任务记着它来自哪份 plan（`from`）→ 节点派生会话去写代码、跑测试、开浏览器验证。**「想清楚」到「做出来」之间，不需要人工把文档重写一遍。**

**还有一处最能说明耦合的**：一个你天天用、但不属于你的后台。先用浏览器自动化去做它，再把重复的那几下固化成一条 tweak——**装一次，之后每次加载都在**。而且 `@target` 声明 + `hits.json`（**只由应用它的东西写、绝不手写**）让「页面改版导致它失效」**有据可查**：是「它停止匹配了」，不是「它从来没匹配上」。把一件会悄悄坏掉的事，变成一件看得见的事。

**远程接入。** 文件和执行留在 hub：在桌面端、浏览器 Web UI 或手机上打开同一个 workspace，看到的是同一个浏览器窗口与同一批文件；需要操作另一台机器时，用设备能力（exec / fs / browser / computer）在**那台机器**上执行——数据不搬回本机，路径语义不变。

## 5. 别处做不到的三件事

1. **同一份文件同时是给人看的、给 agent 用的、给别的工具读的。** 所以「交接」不是导出导入，而是**下一环指向同一个路径**——把 `projects/<slug>/` 整个拷到另一台机器仍然可读，app 删掉也不丢东西。
2. **观察是共享的，并且有记录。** agent 看到的和你看到的是同一个窗口里的同一件事；一条 tweak 现在匹配什么，也有一份不是手写的记录。
3. **判定只有一个来源，而且不会腐烂。** 报告每次从盘上现算：没有索引可以陈旧，没有「已实现」的声明会烂掉；需要解释的部分（还差什么）留在对话里，由人读。

## 6. 不声称的

（每一条都是一次说错话换来的，改这句话线之前先看这里。）

- **不判断「够不够好」。** 覆盖率、「谁实现了谁」已整份删除——它们只能回答「有没有人认领」。链接都通时，本工具**什么都不说**。
- **不保证执行。** `plan` → `task.yaml` 有交接、有来路（`from`），但不保证那些节点会被执行。
- **不提效数字。** 采纳 ≠ 度量。本文只写**可验证的机制事实**，不写「省了多少时间」。
- **不是无人流水线。** 交接点由人按：选模式、挑那份 plan、点生成、装 tweak。自动化程度高，但不是无人。
- **不声称完整的 Office 保真度。** GenOffice 是内嵌的第三方引擎（vendor 资源 + patch）；我们保证的是「同一份文件可被人和 agent 编辑、可导出」，不是替代 Office 的全部行为。
- **不替代** IDE、专业画图工具、浏览器扩展开发。浏览器窗口可能在本机，也可能在 hub 或另一台机器上：远程时依赖网络可达，那台机器的可用性不由本机保证，窗口也不一定在你眼前。

## 7. 怎么自查

1. **加一个能力要加一套机制吗？** 按 [项目分层 §1.1](./requirements/project-layers.md) 那把尺子：应当只有「一个后缀常量 + 一条判据 + 一段措辞 + 页面上一枚 chip」。多出工具 / 通道 / 绑定 / 新页面，就是又走回上一版了。
2. **把一个项目的文件夹整个拷到另一台机器，还读得懂吗？** 应当能。
3. **界面会不会说谎？** 绕开 app 直接改盘上的文件，重开页面即真相。
4. **这个能力把数据和执行放在哪台机器？** 如果只是接入方式（远程窗口、设备 exec/fs、Android），它仍属于同一套底座；如果引入第二份数据或索引，才是违规。
