# Craft Bot — 交互规范

> 状态：规范（不是提案）。实现见 `apps/electron/src/renderer/pages/BotPage.tsx` 与 `docs/global-assistant.md`。
> 一句话：**它是一段对话，右边挂着一张"它开了哪些活"的桌子；桌子有活才出现，出现时只有一个开关。**

> **2026-11-06 现状：入口已摘除。** 侧栏那一行、`mod+j`（`app.openBot`）、紧凑模式入口、以及三处「交给 Craft Bot」都不在了——
> 它们每天被看到，却几乎没被用过（唯一一个 bot 会话是我们自己调 `2+2=` 的）。页面、工作台、服务端通道与本文都还在，
> 所以下面的形态描述仍然准确，只是没有一扇门通向它。要回来只需恢复四处：`AppShell` 的侧栏 `nav:bot` 项、`actions/definitions.ts` 的 `app.openBot`、
> `BotMobileEntry` 的渲染、`App.tsx` 的 `onHandOffToBot`。

---

## 0. 三条原则

1. **对话是主体，别的东西都是旁证。** 面板的默认状态就是一个聊天窗口。任务、产物、状态都从属于它，不能反过来把它挤成一张表单（第一版就是这么错的：composer + 转录 + 任务 + 授权列表竖着堆，开场一大片空白）。
2. **一个意图一扇门。** 在本区干活只有三个工具（`spawn_session` / `create_task` / `send_agent_message`），面上也只有一个"派活"入口。不做第二个入口，不做跨区（§3.2.1）。
3. **有活才出现。** 空的工作台、空的气泡、悬停才亮的"未读"、什么都不做的按钮 —— 一律不存在。**常驻面只允许一个，就是侧栏那一行。**

## 1. 形态

```text
┌ 左栏（侧栏）──────────┬ 对话（ChatPage，占满） ───────────────────────┬ 工作台（关着时不存在）
│ 工作区切换            │  Craft Bot  ● 3 在跑              [▤ 3]        │ 工作台 3           [×]
│ ─────────────────     │                                              │  进行中 2
│ ● Craft Bot   ← 这一行 │  …消息、工具卡、markdown、流式…                │  ● 刷新定价页文案 3/5 节点 40s
│ ─────────────────     │                                              │    重写了首屏和三段…（2 行）
│ 会话 / 筛选 / 标签…    │                                              │    [MD] release.md
│ 项目 / 来源 / 设置…    │  ┌ composer（回车发送）────────────────────┐ │  已完成 2
└───────────────────────┴──────────────────────────────────────────────┴──────────── 300px ─────
```

- **右上角只有一枚按钮：工作台**（`PanelHeaderCenterButton`，与分享/关闭同一种形态），带总数，运行中是琥珀色。关着 = 不存在，**不留下任何可见物**。
- **工作台紧贴助理对话的右边**（`BotWorkbenchDock`，由 `PanelStackContainer` 的 `botDockSlot` 渲染在**助理那一格之后**）。三种摆法里只有这一种对：
  ① 塞进助理面板内部 —— 面板之间共享宽度，再开一个会话面板，聊天被挤成一条而右栏还占着 300px；
  ② 挂到窗口最右缘 —— 之后开的活会跑到工作台右边，答案和问题隔着一个面板；
  ③ **紧邻（现在）** —— 派出去的活就在派它的那段对话身边，**之后打开的面板在工作台右边继续排**。
  它**不参与**面板的比例分配（固定 320px），所以新面板不会吃掉它的宽度；紧凑（移动）模式下它就是整屏一块。
- **没有面板关闭按钮。** 它是目的地，不是一份可以关掉的文档——**作品面板**同样没有 `×`，来的路是侧栏那一行与 `mod+j`，走的路是去别的地方。面板的关闭按钮由 panel slot 通过 shell context 注入，助理这一页在 `BotPage` 里把它置空（只影响这一棵子树）。
- **中间导航栏在 bot 视图下收起**（与作品库同一条规则）——它没有内容可放，空着就是 32% 的浪费。
- 宽度：dock 固定 320px（`DOCK_WIDTH`），拖拽留给以后；聊天在面板行里始终 `flex-1`。
- 数据只有一个来源：`atoms/bot-workbench.ts` 里的单例轮询（第一个订阅者启动、最后一个停止），助理标题旁的 `N 在跑`、开关上的数字、dock 里的列表读的是同一份快照。

## 2. 四个入口，各自一件事

| 入口 | 位置 | 作用 | 不要做 |
|---|---|---|---|
| 侧栏那一行 | 工作区切换器下方，一条细线分隔 | 打开/聚焦 bot 面板 | **不进**工作区列表；不是第 N 个工作区 |
| `mod+j` | 全局 | 同上，并把光标放进输入框 | 不要占 `mod+k`（留给搜索/命令面板） |
| 「交给 Craft Bot」 | 会话菜单、项目页、作品卡 | 把当前上下文变成一句 brief 放进草稿 | **不自动发送** |
| 未读点 | 侧栏那一行上，**常显** | 它在你不在看时回了话 | 不要用悬停才亮的 `label`（看不见的标记不算标记） |

## 3. 聊天头：名字是名字，不是一张会话菜单

助理的头由 `ChatPage` 的 `assistantHeader` 给出，**不另起一条 bar**——一个对话两个标题是错的。它替换掉会话头的两半，而不是往上面加东西：

| 位置 | 会话（普通） | 助理 |
|---|---|---|
| 标题 | 可点，下拉是**会话动词**：分享、移到项目、标签、看板列、标旗、归档、删除、在新窗口打开 | 可点，下拉是**助理自己的动词**：目前只有**连接消息平台**（把它绑到 Telegram / WhatsApp / 飞书，用手机给它派活）。会话那些动词一个都不在 |
| 标题旁 | 徽标（状态/agent 等） | `● 3 在跑`（琥珀，只在有活时）；`Explore`（琥珀，只在 `safe` 时，带"它不能开活"的解释） |
| 右侧 | 分享（或紧凑态的信息）、任务铅笔、右栏开关、**关闭面板** | **只有工作台开关**（带计数，琥珀 = 有活）；**没有关闭** |

**为什么"移到项目"这类东西必须走**：助理没有归档位置，不在看板上，也不是能发给别人的链接。它是一段对话 + 一张桌子；那些动词在这里要么无效、要么危险（把助理移进项目后它就不在侧栏那一行了）。

**但"连接消息平台"必须留下**：它把这段对话绑到一个 IM 机器人上，于是你在手机上发的一句话，就是在这儿派出去的活。那是助理最该有的一条动词——第一版把这整张菜单删掉时，它被一起删了，是错的。判据不是"这个菜单属于哪种面板"，而是**逐条问这个动词对助理成不成立**。

**工作区 · 模型 · 权限去哪了**：composer 上本来就写着模型和权限模式（那是你改它们的地方），侧栏写着当前工作区。头部再抄一遍是重复；唯一例外是 `Explore`——它会让"派活"静默失效，所以它留在可见处并带解释。

## 3.5 输入框：同一个 composer，去掉「这条会话的管道」

助理用的是**跟会话一模一样**的 `ChatInputZone`——不新写一个，理由和面板复用 `ChatPage` 相同：抄一份只会更差，而且会漂移。

| 部分 | 助理 | 为什么 |
|---|---|---|
| `@` 引用（来源 / 技能 / 文件 / 浏览器标签） | **保留，完整可用** | 引用资源是在"写这句话"，助理比会话更常需要它（"用 `@Sources` 里的那套规范改"）。Trae 的助理也保留 `@` 与 `/` |
| `/` 命令（`/compact`、清空、目录层…） | **保留** | 同上；`/compact` 对一条长会话尤其有用 |
| 附件、模型、权限模式、排队、引用回复 | 保留 | 都是"这一段对话"自己的事 |
| `#` 标签、看板状态 | **去掉** | 助理不在看板上，也不归档到任何地方 |
| 工作目录选择器 | **去掉**（但目录本身照传） | 它在工作区根上干活，子会话自己决定目录；文件搜索仍需要这个基准路径 |
| placeholder | **换成一句它是什么** | `让它在这个工作区做点什么…`——会话那边轮播的是快捷键提示，对助理没意义 |

一句话记法：**凡是写进这条消息的东西都留，凡是配置这条会话的东西都去掉。**

## 4. 工作台

> 它是"这个对话开了哪些活，各自怎么样了"，不是第二份会话列表。

### 4.1 头部

`工作台 N` + **一枚 `×`**（右上）。这一行 **42px**。

**这里的 `×` 是对的，面板头上那个不是**：面板是目的地（关了等于把对话删了），dock 是工具面板（关了就是收起来，东西还在）。同理"最近的整块"规则也成立：`Esc` 先收 dock。
**没有刷新按钮**：列表跟 `bot:changed` 推 + 5s 兜底，一个手动刷新只会让人问"刷的是什么"。
**不用 `›` 收起**：右栏上的右向箭头读起来是"展开/进入"。

### 4.1.1 分组

两个，按"此刻还要不要看"分：**进行中** / **已完成**（`running` / 其余）。组标题带计数，**空组不出现**——安静的桌面就该是短的。不做全部/运行中/已完成的分段控件：那是一个只有三个选项、却要占一行的地方。

抬头那个数字是**屏幕上卡片的数量**，不是"一共开过多少活"——抬头与自己的列表对不上，是第一眼就会被看穿的那种错。

### 4.1.2 上限：它会堆，所以必须有边界

**这张桌子是「现在」的表盘，不是「我派过的所有活」的档案。** 三者混在一起，一周之后就没人再打开它了——一个越读越长的列，第三天后就等于不存在。

| 类别 | 规则 |
|---|---|
| 进行中 | **全列**。它天然有限：同时在跑的就几个，不会随时间增长 |
| 已完成 | **只留最新的 8 张**（按 `lastMessageAt` 倒序） |
| 更早的 | 折成**一行**：`还有 12 条更早的 · 在会话列表里`，点它去会话列表 |
| 已归档的子会话 | **不出现**。归档是"这件事我完了"的表示，比任何时间窗都准 |

**为什么不是"按时间衰减"或"按未读筛"**：

- 按时间（比如 24h）只是把堆积推迟了——一个周末不做活，回来还是一片。
- 按未读也不行：没人点开过的子会话永远是未读，于是"未读"自己又变成无界的。未读只用来**点颜色**（琥珀 = 你不在时回来的，灰 = 已看过），不用来筛。

真正的档案在别处，而且本来就在：**子会话是普通会话**，它们躺在会话列表里，有搜索、有归档、有项目；产物在作品库里。工作台不抄一份。

所以一块卡片的存在理由只有三条，其余都该沉下去：**它还在跑**、**它刚回来而你没看**、**它的结果我马上要用**。第三条只对最近成立——这正是 8 张上限的意思。

### 4.2 卡片

卡片用**看板卡片那一套视觉**（`rounded-lg` · `border-border/50` · 2% 前景底 · `shadow-minimal` · 8px 间隔）：工作台里装的是同一种东西——一件待办，形状也该一样。行与行之间靠底色差而不是靠线，否则四张卡就成了一张表。

| 行 | 内容 |
|---|---|
| 状态点 + 标题 | 点居中于标题首行；琥珀 = 在跑，灰 = 空闲/完成。标题 13px medium，单行截断 |
| 副行 | `3/5 个节点`（`kind: 'task'`）· 相对时间（`40s` / `2h` / `3d`，所有卡片都有）。**不写工作区名**——一个窗口只有一个区，那是平台事实，不是卡片信息 |
| 正文 | 它最后说的那一段，**最多 2 行**（点开有全文；三行会把一屏吃掉一半） |
| 产物 | 小 chip：`[MD] release.md`；点开用应用内阅读器；已删的划掉 |
| 操作 | **整行点击 = 在助理旁边开一屏**（`newPanel`，与 `mod+单击` 会话同一动作，见 §7）；`■` 停止，**悬停才出现**，角标位置与看板的铅笔一致，只占标题行的位置（正文照旧全宽） |

卡片本身**没有** `↗` 图标（整行已经是那个动作），也**没有**第二排按钮。

### 4.3 空态

一句话，不解释机制：

> 还没有任务。让它在这儿做点什么，结果会出现在这里。

**不要**出现"最近任务/项目任务/产物"三个分区标题——那是一个空抽屉里的抽屉。

## 5. 状态与边界（这些是最容易做歪的）

| 情形 | 必须这样 | 不许这样 |
|---|---|---|
| **首次打开** | 直接是可输入的对话；空对话里有 2–3 枚示例（"把这件事办了" / "先拆成几步"） | 空白面板 + 一个下拉框 |
| **没有模型/连接** | 聊天头写 `no model`，可一键去设置 | 悄悄用默认值，然后在失败时只报"出错了" |
| **Explore 模式** | 权限徽标显示 `safe`；尝试派活时**明说**"这个区在 Explore，我不能动手" | 工具悄悄不出现，模型编一个理由 |
| **任务在跑** | 工牌计数 + 卡片琥珀点；列表照常可读 | 弹 toast、阻塞输入 |
| **任务结束** | 助理在对话里用一两句话讲结果（回话闭环）；侧栏出现未读点 | 只更新卡片，一句话不说 |
| **失败** | 卡片 `failed` + 最后一段错误；助理同样开口讲 | 静默停在 running |
| **排队消息** | 只显示**人写的**消息（`hidden` 的系统消息永不进托盘） | 把系统 nudge 显示成"待发送" |
| **两个窗口同区** | 共享同一个 bot 会话（`bot:session` 单飞） | 各建一条 |
| **对话很长** | 允许 `/compact`；上下文吃紧时在 composer 附近给一枚提示 | 到顶了才报错 |

## 6. 键盘

| 键 | 作用 |
|---|---|
| `mod+j` | 打开/聚焦 Craft Bot，光标进输入框 |
| `Enter` / `Shift+Enter` | 发送 / 换行（composer 原有行为） |
| `Esc` | 工作台打开时先关工作台，再退出面板 |
| `Tab` 在工作台内 | 在卡片间移动；`Enter` = 打开那一条 |
| 回复某条消息 | 回答上的动作栏里「回复」；引文条在输入框上方，点引文条跳回原消息 |

## 7. 明确不做

| 不做 | 原因 |
|---|---|
| 对话列表 / "新建对话" | Trae 也没有：一条主线 + 每个任务一条子会话，历史由工作台与记忆承载。真需要重开，归档当前会话即可（`bot:session` 取最新非归档）。 |
| 跨区派活 / 授权 | 已拆除，见 `docs/global-assistant.md` §3.2.1。 |
| 常驻悬浮球 | 常驻面只允许一个；要有也是**有租约的胶囊**（§9）。 |
| 工作台放左边 | 与 Trae 相反，且左栏是工作区的空间。 |
| 每个任务开一个独立窗口 | 卡片点击是**在助理旁边开一屏**，不是弹一个 OS 窗口：窗口会把人从"马上要收到结果的那个对话"里带走。 |
| 卡片上的第二排按钮 | 一个主操作（整行）+ 一个次要操作（停止）是上限。 |

## 8. 验收（照着点一遍）

1. 首次打开：直接能打字；没有工作台；侧栏那行没有未读点。
2. 让它开一个子任务：标题旁出现 `● 1 在跑`，右上角那枚按钮变成 `1`；工作台里"进行中"一张卡，琥珀点、相对时间、两行正文；**队列托盘里没有任何系统消息**。
3. 任务结束：助理在对话里说了一句结论；卡片转灰；侧栏出现未读点；产物可点开。
4. 点标题：**没有下拉**（没有移到项目/标签/分享）；右上角只有工作台一枚。关掉工作台：**宽度归零，没有残条**；`mod+j` 再次打开它。
5. Explore 模式下让它派活：它**说出来**为什么不能，而不是沉默。
6. 两个窗口同一个区：`mod+j` 两边进的是同一条对话。
